\section{Preregistered Execution and Inference}

\subsection{Immutable Workflow and Gates}

The linear workflow is \texttt{prepare},
\texttt{diagnose-finance-complex}, \texttt{preflight}, \texttt{develop},
\texttt{pilot}, \texttt{gate}, \texttt{run}, \texttt{validate},
\texttt{analyze}, and \texttt{build-paper}. The immutable main manifest binds
resolved configuration; source, artifact, code, prompt, checker, retriever,
system, dependency, preflight, and pilot-gate hashes; exact case, document, and
stratum inventories; exact expected cell keys; exact model, deployment, and
tokenizer identity; retry and failure policy; secret-free credential patterns;
and a clean Git commit. Mutable progress appears only in
\texttt{run\_state.json}. Every downstream stage verifies upstream hashes before
parsing artifacts.

Preflight requires the requested and response-resolved model to equal exactly
\texttt{gpt-5.4-mini}. It also requires strict JSON, authoritative prompt and
completion usage, the frozen tokenizer identity and hash, and equality between
the exact pre-call prompt count and gateway usage. Missing tokenizer support or
any model substitution stops the workflow.

The operational pilot gate is non-overridable. It requires a complete unique
paired grid; authoritative usage; zero leakage and budget overruns; at least
99\% schema validity; at most 1\% unresolved external matched blocks; exact
mechanism counts; low-tier feasibility; at least 20\% median verified-search
token growth between adjacent tiers; easy monolith accuracy at least 90\%; hard
monolith accuracy between 30\% and 85\%; checker specificity at least 95\% and
sensitivity at least 60\%; correct-to-wrong repair at most 5\%; and correction
of at least 20\% of checker-detected wrong first drafts. A failed component
blocks the main run.

\subsection{Power and Confirmatory Inference}

Internal-pilot sizing uses only low/high paired discordance with architecture
identity and direction masked. Exact one-sided McNemar power targets 90\% for a
five-point alternative. If required hard $N\le900$, the allocation is 900 hard
plus 100 easy. For $901\le N\le1000$, hard receives the required $N$ and easy is
reduced to keep 1,000 total. If $N>1000$, the study stops as underpowered without
unblinding. Repeated generations never increase the independent sample size.

For each independent document, architecture failures are incorrect and
unresolved external infrastructure blocks are excluded as complete matched
blocks. The two one-sided exact McNemar tests use $\alpha=.05$ each because the
claim is an intersection-union test. We report ordinary paired differences,
one-sided bounds, two-sided cluster-bootstrap intervals, and five-point SESOI
interpretations. A crossover is confirmed only if the low difference is
strictly negative, the high difference strictly positive, and both directional
tests reject. A high-only result is labeled \texttt{threshold\_benefit\_only}.

The cluster bootstrap resamples documents and carries all systems and tiers
together. Non-crossing replicates are retained. A transition is estimated only
after observed endpoint reversal; the report includes crossing support, a
conditional numeric interval, and a confidence set that includes no crossing
when applicable. Exploratory families use Holm adjustment or simultaneous
cluster bands. Pareto probabilities are separate for accuracy against realized
tokens, cost, and latency.

\subsection{FinanceComplexQA Diagnostic Boundary}

FinanceComplexQA is restricted to the pinned Pro, English,
Numerical-Comparison subset, deduplicated by canonical question/document
identity, with an expected count of 113. Count discrepancy aborts. Its four
boundaries are: scorer gold round-trip plus adversarial perturbations; reference
lineage and zero leakage; model behavior with oracle evidence; and reference,
planned-query, and production retrieval ladders with pre/post truncation recall.
Exploratory system execution requires 100\% scorer correctness, 100\% reference
linkage, zero leakage, and at least 95\% high-tier reference-document recall.
This domain is never pooled into confirmation.
